LUMINA — Blockchain Order Verification

Blockchain Integration • Smart Contracts • Web3

Solidity Hardhat Hardhat Ignition Viem Node.js PostgreSQL

Overview

Extended LUMINA, my AI-powered multi-vendor e-commerce platform, with a blockchain-based order audit trail. The system uses a Solidity smart contract to record important order lifecycle events such as CREATED, READY_FOR_PICKUP, OUT_FOR_DELIVERY, and DELIVERED.

PostgreSQL remains the primary application database, while blockchain is used selectively to create a tamper-evident record of important order events. This hybrid architecture provides the flexibility of a traditional database with the security guarantees of blockchain.

What I Built

Smart Contract

Developed OrderVerification Solidity contract to store order status history and timestamps on-chain.

Blockchain Network

Used Hardhat to run a local Ethereum-compatible blockchain for development and testing.

Contract Deployment

Used Hardhat Ignition for automated smart contract compilation, deployment, and verification.

Web3 Integration

Used Viem to interact with deployed smart contract from Node.js backend using contract ABI.

Order Audit Trail

Successfully recorded multiple order lifecycle events on-chain with transaction confirmation.

Hybrid Architecture

PostgreSQL handles application data while blockchain provides verification for critical order events.

System Architecture

Hybrid architecture: PostgreSQL handles application data while blockchain provides a tamper-evident order audit trail.

LUMINA Frontend (React) → Node.js Backend (Express)

Hardhat Local Blockchain (Ethereum-compatible)

Why Blockchain?

Traditional order information is stored in the application's database. For selected critical events, blockchain provides an additional tamper-evident record. This allows LUMINA to verify that a particular order status was recorded at a specific point in time without replacing the existing database architecture. The blockchain serves as a trust layer for important order lifecycle milestones.

pragma solidity ^0.8.20;

contract OrderVerification {
  struct OrderEvent {
    string status;
    uint256 timestamp;
  }

  mapping(string => OrderEvent[]) private orderHistory;

  event OrderStatusRecorded(
    string indexed orderId,
    string status,
    uint256 timestamp
  );

  function recordOrderStatus(
    string memory orderId,
    string memory status
  ) public {
    orderHistory[orderId].push(
      OrderEvent({status: status, timestamp: block.timestamp})
    );
  }
}

pragma solidity ^0.8.20;

contract OrderVerification {
  struct OrderEvent {
    string status;
    uint256 timestamp;
  }

  mapping(string => OrderEvent[]) private orderHistory;

  event OrderStatusRecorded(
    string indexed orderId,
    string status,
    uint256 timestamp
  );

  function recordOrderStatus(string memory orderId, string memory status) public {
    orderHistory[orderId].push(OrderEvent({status: status, timestamp: block.timestamp}));
    emit OrderStatusRecorded(orderId, status, block.timestamp);
  }

  function getOrderHistory(string memory orderId) public view returns (OrderEvent[] memory) {
    return orderHistory[orderId];
  }
}

5

Verification

Order history can be retrieved from the blockchain for verification.
